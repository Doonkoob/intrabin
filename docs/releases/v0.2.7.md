# Intrabin v0.2.7

Panel updates now use prebuilt release images by default for existing GitHub source installations.
They avoid local Node, Go and Python base-image downloads that can fail with Docker Hub 403 errors.

- Tagged updates automatically switch source installs to release images and keep that mode for
  subsequent updates. Existing custom image registries are preserved.
- GHCR pulls fall back to public GitHub release archives when registry access fails.
- Image preparation and container startup remain sequential, with the normal backup and rollback
  if image preparation fails. Cluster identities, accounts and data volumes are preserved.
- `intrabin update --to vX.Y.Z --build` explicitly selects a local build. Branch-based source
  updates and source repositories outside GitHub keep their existing build behavior.

## Upgrade a host whose updater still builds locally

Old host scripts execute their already-loaded update function even after checking out a new tag.
Use the tagged bootstrap once on each affected host:

```bash
curl -fsSL https://raw.githubusercontent.com/Doonkoob/intrabin/v0.2.7/scripts/update.sh -o /tmp/intrabin-update.sh &&
sudo bash /tmp/intrabin-update.sh v0.2.7 /opt/intrabin
```

Subsequent tagged updates from the panel use the new behavior. Existing clusters do not need to
be initialized or joined again.
