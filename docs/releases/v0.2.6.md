# Intrabin v0.2.6

Cluster members are easier to identify, and joining waits until the cluster account data is ready.

- Overview shows the actual cluster mode, leader, reachable member count and quorum instead of
  fixed standalone values. Node information is also visible before creating the first monitor.
- Node labels use their public URL or cluster address plus a short persistent ID. Installations
  with identical hostnames stay distinct, and IDs survive updates and restarts.
- The cluster member list shows each node's running version. Live heartbeats refresh names,
  public URLs and versions instead of relying only on enrollment metadata.
- Joining waits for the leader's replicated state, including usernames and password hashes,
  before reporting success. Local accounts are replaced using the selected export/discard mode.
- Follower login waits until a forwarded session has actually been written to its local database.
  An incomplete synchronization returns an error instead of reporting the session ready.

Update the leader and all members to v0.2.6. Existing node IDs, monitoring history and cluster
membership are preserved; there is no need to recreate a healthy cluster.
