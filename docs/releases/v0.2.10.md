# Intrabin v0.2.10

Fixes host-agent setup and makes node renaming visible in the first table column.

- **Rename node** is beside the node name, so it is accessible without scrolling to the Actions
  column. Only the leader's authorized administrators can use it.
- Installers and successful CLI updates install or repair the systemd update watcher and a
  recovery timer. The timer checks for queued requests every 30 seconds.
- Agent availability is reported only when the watcher or recovery timer is actually active.
  A previously written `agent.json` no longer makes a newly checked, unconfigured host look ready.
- The agent waits for a running deployment's lock instead of exiting immediately and potentially
  exhausting systemd's path-trigger start limit.
- If no agent reports starting a cluster request within five minutes, the rollout pauses with an
  actionable error. It does not restart the next node while the first request remains unresolved.
- Settings no longer displays the green “No update available” card while a cluster rollout is
  still running or failed.

## Repair an existing host with missing or failed update units

Run once on each affected server. This installs the host agent without changing the running
version, database, accounts, images or membership, and picks up an already queued request:

```bash
curl -fsSL https://raw.githubusercontent.com/Doonkoob/intrabin/v0.2.10/scripts/update-agent.sh -o /tmp/intrabin-update-agent.sh &&
sudo bash /tmp/intrabin-update-agent.sh /opt/intrabin
```

If the cluster plan has already failed, use **Retry cluster update** on the leader after repairing
the affected host. Once the current rollout finishes, update the cluster to v0.2.10 normally.
Hosts already running the new CLI can use `sudo intrabin repair-update-agent`.
