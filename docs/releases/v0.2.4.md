# Intrabin v0.2.4

Updates on servers with restricted registry access no longer need local builds.

- `intrabin update --to v0.2.4 --prebuilt` switches an existing source installation to published images.
- If GHCR cannot be reached or rejects anonymous access, the updater downloads the matching image
  archive from the public GitHub release and loads it locally. Both amd64 and arm64 are supported.
- Cached, versioned images such as Caddy are reused without contacting Docker Hub.
- Image preparation and container startup run one service at a time. Manual and web updates share
  the same lock to prevent overlapping deployments.
- `scripts/update.sh` runs the selected release's updater even when the installed updater is old.
  It backs up before replacing installation files, and restores the old configuration if image
  preparation fails. Existing containers continue running until image preparation succeeds.

## Recover an old updater

Run once on each affected host (change `/opt/intrabin` if installed elsewhere):

```bash
curl -fsSL https://raw.githubusercontent.com/Doonkoob/intrabin/v0.2.4/scripts/update.sh -o /tmp/intrabin-update.sh &&
sudo bash /tmp/intrabin-update.sh v0.2.4 /opt/intrabin
```

The next panel update uses the installed updater and prebuilt images. GitHub must be reachable;
an uncached proxy image still requires access to its registry. No Docker login is needed for the
public release archives.
